# 수동 테스트 결과

`03_개발 컨벤션.html`의 수동 테스트 시나리오 표와 `docs/작업계획서.md` §3-3을 기준으로, 이슈 #1~#11 구현이 모두 머지된 `main` 기준에서 하나의 연속된 세션으로 전체 시나리오를 재검증한 기록이다. 각 시나리오는 개별 PR 리뷰에서도 검증됐지만, 이번엔 기능 간 상호작용(관리자 조작 → 방문 기사 화면 반영 등)까지 이어서 확인했다.

## 테스트 환경

- `docker compose up -d db` + 로컬 `./gradlew bootRun` + `npm run dev` (프론트 5173 → 백엔드 8080 직접 호출)
- 시드 데이터: 활성 창고(서울1센터, 도크 A1/A2), 비활성 창고(비활성창고, 도크 B1), 도크 없는 창고(도크없는창고), 관리자 계정 1개

## 결과

| 시나리오 | 확인 방법 | 기대 결과 | 실제 결과 |
|---|---|---|---|
| 동시 배정 충돌 | 같은 도크(A1)에 두 요청을 백그라운드로 동시 전송 | 하나는 201, 하나는 409 | ✅ 201/409 정확히 하나씩 |
| PIN 불일치 | 성공한 배정을 잘못된 PIN으로 취소 요청 | 401 PIN_MISMATCH | ✅ `{"code":"PIN_MISMATCH", ...}` |
| 비활성 창고 신규 배정 차단 | 비활성 창고 소속 도크(B1)에 배정 시도 | 403 WAREHOUSE_INACTIVE | ✅ `{"code":"WAREHOUSE_INACTIVE", ...}` |
| ACTIVE 배정 있는 도크 비활성화 차단 | 관리자 화면에서 배정 중인 도크(A1) 비활성화 클릭 | 400 DOCK_HAS_ACTIVE_ASSIGNMENT, 화면에 에러 문구 노출 | ✅ 에러 문구 렌더링, A1은 계속 활성 상태 유지 |
| 비활성 도크 노출 여부 | 관리자가 배정 없는 도크(A2) 비활성화 → 방문 기사 화면(`/w/1`) 재조회 | 목록에서 A2 제외 | ✅ 방문 기사 화면에 A1만 노출 |
| AI 요약 데이터 없음 | 도크 없는 창고의 요약 조회 | occupancyRate=0, 기본 안내 문구, LLM 호출 없이 즉시 응답 | ✅ "등록된 도크가 없어 혼잡도를 계산할 수 없습니다." |

## 완료 정의(DoD) 대조

- [x] 관련 API가 API 설계서(`콕배정-API.yml`)의 요청/응답 스펙과 일치한다 — 이슈 #1~#11 각 PR 리뷰에서 개별 확인
- [x] 설계_v4의 에러코드가 실제 해당 예외 상황에서 발생한다 — 위 표에서 재확인
- [x] 빌드가 깨지지 않는다 — `main` 기준 `./gradlew compileJava`, `npm run build` 모두 통과
- [x] 로컬에서 실제 요청을 보내 정상 응답을 눈으로 확인했다 — curl + Playwright(실제 Chrome, 모바일 뷰포트)로 확인
- [x] 요구사항_정의서에 명시된 예외 케이스가 하나도 빠지지 않았다 — 위 6개 시나리오 전부 통과
